## Что где лежит

| Файл | Что в нём |
|---|---|
| `ds/tokens.css` | Токены: цвета, шрифт, скругления, ключевые размеры |
| `ds/components.css` | Компоненты на токенах: шапка, таб-бар, карточки, календарь, кнопки, поля и т. д. |
| `design-system.html` | Живая страница: все токены и компоненты отрисованы теми же файлами, у каждого подписано, где он используется |
| `index.html` | Приложение. Подключает оба файла ДС; в своём `<style>` держит только оболочку прототипа и стили экранов, которые уходят в #2 |

Места использования каждого токена и компонента ведутся на живой странице
(одно место, чтобы не расходилось), здесь — правила.

## Откуда взялись значения

ДС собрана из прототипа (`index.html`, коммит `f996da0`), только из экранов,
которые остаются в первом этапе (#2): «Мероприятия» (календарь), «Карточка
мероприятия», «Партнёр», «Профиль», «Настройки профиля». Значения
фактические, без «шкал для полноты». Элементы только с убираемых экранов
(поиск, чипы, галерея, карта участника с QR, шторка, переключатели) и
оболочка прототипа (рамка телефона на десктопе) в ДС не входят — список на
живой странице, раздел «Не входит в дизайн-систему».

Брендбука у клуба пока нет (см. вопрос 7 на живой странице).

## Правила

1. Экраны — и макеты, и код — собираются только из компонентов и токенов ДС.
2. В `ds/components.css` нет цветовых литералов, только `var(--…)`. Каждый
   токен из `ds/tokens.css` где-то используется, и каждый описан на живой
   странице. Это проверяет `npm test` (`tests/ds.test.mjs`).
3. Нужного компонента в ДС нет — его не рисуют и не кодируют молча: сначала
   обсуждаем с владельцем, подходит ли существующий; новый компонент или
   токен появляется в ДС только после его явного «ок».
4. Если экран или макет расходится с ДС, выбирать молча нельзя: расхождение
   выносится владельцу списком «где — что на экране — что в ДС».
5. Новый элемент ДС попадает сразу в три места одним PR: `ds/*.css`,
   живая страница (с местом использования), при необходимости — этот файл.
