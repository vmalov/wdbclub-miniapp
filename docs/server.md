## Авторизация

- Каждый запрос к `/api/*` несёт заголовок `Authorization: tma <initData>`
  (строка `Telegram.WebApp.initData`).
- Сервер проверяет подпись по алгоритму Telegram: `secret = HMAC_SHA256("WebAppData", BOT_TOKEN)`,
  `hash == HMAC_SHA256(secret, data_check_string)`; `auth_date` не старше 24 часов.
  Не прошло → `401`, приложение показывает «Откройте приложение из Telegram».
- Пользователь — `user.id` из `initData`; имя, `@username`, фото обновляются
  при каждом запросе.
- Вне Telegram (браузер) приложение данных не получает: экран «Откройте в
  Telegram» со ссылкой на @wdbclub_bot. Для e2e — тестовый токен бота на
  локальном сервере, подписанный `initData` генерирует тест.

## Модель данных (SQLite)

| Таблица | Поля |
|---|---|
| `users` | `id` (Telegram ID), `name`, `username`, `photo_url`, `created_at`, `seen_at` |
| `events` | `id` (`voyage`), `type`, `name`, `date`, `time`, `gather`, `place`, `address`, `desc`, `cap`, `cover`, `partner_id` |
| `cars` | `id`, `user_id`, `brand`, `model`, `year`, `color`, `plate`, `show_plate`, `photo` (имя файла в `photos/`), `created_at`, `deleted_at` |
| `regs` | `event_id`, `user_id`, `car_id`, `status` (`on` / `wait`), `created_at`; уникальны `(event_id, user_id)` |
| `prefs` | `user_id`, `last_car_id` |

Мероприятия заводятся из `server/events.json` при старте (upsert по `id`).
С #10 — Yellow Night 13.11, `cap` 50, `noCar: true` (запись без машины,
`regs.car_id` может быть `NULL`; база прежней схемы мигрирует при старте).
С #23 — поле `peopleOrganizerOnly: true` («список участников видит только
организатор», столбец `events.people_org_only`, по умолчанию 0; база
прежней схемы мигрирует при старте); у Yellow Night включено.
Мероприятие, которого нет в файле, удаляется, если на него нет записей, иначе
остаётся (в лог — «оставлены»). Правка мероприятий — правкой файла и
выкаткой; админки нет.

Фото машины приходит в теле запроса как JPEG data URL (фронт уже ужимает до
900 px), не больше 1,5 МБ; сервер сохраняет файл `photos/<uuid>.jpg` и
отдаёт по `/photos/<uuid>.jpg` без проверки подписи: фото открываются как
фон/`<img>`, заголовок туда не передать. Имя файла — случайный UUID, список
файлов не отдаётся, перебрать нельзя.

## API

Все ответы — JSON. Ошибки — `{ error: '<код>' }` с HTTP-кодом.

| Метод и путь | Что делает | Ошибки |
|---|---|---|
| `GET /api/state` | Всё для экранов: `me` (`id`, `name`, `tg`, `photo`, `organizer`), `cars`, `lastCarId`, `events` — см. ниже | 401 |
| `POST /api/events/:id/register` `{ carId }` | Записать: места есть → `on`, нет → `wait`. Ответ — `{ status }` + новый `state` | `no-car`, `bad-car`, `past`, `already` (409), `not-found` (404) |
| `DELETE /api/events/:id/register` | Отменить запись / выйти из очереди. Если отменял `on` — первый по времени из `wait` становится `on`. Ответ — новый `state` | `not-registered` (409) |
| `POST /api/cars` `{ brand, model, year, color, plate, showPlate, photoData? }` | Новая машина; проверка — те же правила, что `validateCar` | `invalid` (400) + `errors` |
| `PUT /api/cars/:id` | Изменить свою машину; `photoData` не передан — фото прежнее | `invalid`, `not-found` |
| `DELETE /api/cars/:id` | Удалить свою машину (мягко, `deleted_at`) | `in-use` (409) — машина в записи (`on`/`wait`) на мероприятие, которое ещё не прошло |

**Мероприятие в `state.events`** (как в коде, `stateFor` в `server/core.mjs`;
описание выровнено с кодом в #23): поля мероприятия (в том числе `noCar`,
`peopleOrganizerOnly`) + `others` — другие записанные (`on`), `waitOthers` —
другие в очереди, `myWaitPos` — моё место в очереди или `null`; моя запись —
в `state.regs`. Полные карточки (имя, `@username`, машина, госномер, если
владелец разрешил) — если я записан, в очереди или организатор; иначе
обезличенно: инициалы и фото машины.

**Список видит только организатор (#23):** у мероприятия с
`peopleOrganizerOnly` не-организатору (записан он или нет) приходят
`others: []`, `waitOthers: []` и числа `othersCount` (другие `on`) и
`waitCount` (другие в очереди) — ни имён, ни инициалов, ни фото. Фронт
считает места и «перед вами в очереди» по этим числам, если они есть
(`seatsTaken`, `queueAhead` в `app/logic.js`). Организатору — как обычно.

**Транзакции:** запись и отмена — в `BEGIN IMMEDIATE`: подсчёт мест,
вставка и продвижение очереди атомарны. Два человека на последнее место:
один получает `on`, второй — `wait`.

**Организаторы:** `ORGANIZERS` в `/etc/wdbclub/env` — Telegram ID через
запятую. Организатор видит полный список и очередь любого мероприятия и
отмечен «организатор» в профиле. Запись организатора — как у всех. На
12.11.2026 список пуст — организаторов нет (#23).

## Изменения во фронте

- `app/store.js` → `app/api.js`: загрузка `state`, вызовы API; при ошибке
  сети — тост «Нет связи, попробуйте ещё раз», состояние не меняется.
- `app/logic.js`: правила записи остаются для проверки формы и отображения;
  места и очередь считаются по `taken`/`waitCount`/`my` с сервера. Юнит-тесты
  правил на фикстурах сохраняются.
- `app/data.js`: выдуманных участников и мероприятий в приложении нет;
  мероприятия приходят с сервера. Фикстуры остаются в `tests/fixtures/`.
- Пока грузится `state` — экран-заглушка (логотип), без мигания пустого
  списка.
- **Удаление машины** (`docs/screens/car.md`): под карточкой рядом с
  «Изменить» — ссылка `.link` «Удалить». Нажатие → шторка `.sheet`
  «Удалить <модель>?» с `.btn` «Удалить» и `.link` «Отмена» (существующие
  компоненты ДС, нового нет). После удаления — профиль и тост «Машина
  удалена». Сервер ответил `in-use` — тост «Машина записана на „<название>“ —
  сначала отмените запись».
- Отмена записи продвигает очередь на сервере; участник из очереди увидит
  «Записаны», когда откроет приложение (уведомлений бота нет — решение
  владельца 10.11.2026).

## Не входит

Уведомления от бота, админка мероприятий, отправка ошибок в GlitchTip,
аналитика, перенос машин из `localStorage` прототипа (кто пробовал Pages —
заведёт машину заново).
