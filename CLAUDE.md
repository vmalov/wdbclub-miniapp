# wdbclub-miniapp — контекст проекта

Telegram-мини-апп клуба WDB Club (клуб владельцев Mercedes-Benz,
https://wdbclub.com/). Первый этап (#2) — прототип без сервера: мероприятия
и участники вымышленные (`app/data.js`), свои машины и записи — в
`localStorage` (`app/store.js`). Без сборки: `index.html` + ES-модули `app/`
(`logic.js` — правила, `views.js` — экраны, `main.js` — навигация и
Telegram). Правила записи — `docs/registration.md`. Публикуется через
GitHub Pages из `main`: https://vmalov.github.io/wdbclub-miniapp/

Процесс — `PROCESS.md` из `vmalov/dev-guides` (тикет → DoD → дизайн → ТЗ →
код и тесты → PR → мердж владельцем). Документы экранов —
`docs/screens/` по шаблону `_template.md`, индекс — `docs/screens/README.md`.

## Дизайн-система — обязательна

Описание и решения — `docs/design-system.md`, живая страница —
`design-system.html`, файлы — `ds/` (#1). Светлая тема сайта клуба,
антиква Oranienbaum + гротеск Tilda Sans, референс — Mercedes-Benz
Community.

- Экраны (и макеты, и код) собираются только из компонентов, токенов и
  иконок ДС. Цветов, шрифтов и скруглений мимо токенов нет.
- Нужного компонента в ДС нет — не рисовать и не кодировать молча: сначала
  предложить владельцу похожий существующий или новый; новый появляется в
  ДС (CSS + макет + живая страница с местом использования) только после
  его явного «ок».
- Расхождение экрана или макета с ДС — владельцу списком «где — что на
  экране — что в ДС», правка только после его решения.
- Звезду Mercedes-Benz и шрифты MB Corpo не использовать: товарный знак и
  лицензия. От Mercedes-Benz Community берём принципы, не графику.

## Макеты и сценарии

Лежат в репозитории (решение владельца 09.11.2026, #1):
`mockups/stage-1.html` — все экраны с номерами S1…, `mockups/flows.html` —
те же экраны по сценариям (шаги, место нажатия, действие). Экраны описаны
один раз в `mockups/screens.js`. Владелец смотрит сценарии артбордом —
новый экран добавляется и в общий список, и в нужный сценарий.

Фото в макетах — с сайта клуба; госномера на фото скрываются, людей в кадре
не берём.

## Превью для согласования

`node tools/build-preview.mjs <файл.html>` собирает сценарии, все экраны и ДС в один
самодостаточный HTML (шрифты, фото и иконки вшиты) — его публикуют артефактом
claude.ai и дают владельцу ссылку. raw.githack.com для превью не годится: с ноября
2026 показывает браузеру промежуточную страницу, и стили со шрифтами не грузятся.

## Тесты

`npm test` — юнит-тесты правил (`tests/logic.test.mjs`) и проверки ДС
(`tests/ds.test.mjs`, в том числе «приложение — только классы ДС»).
`npm run e2e` — сценарии в видимом Chrome (`tests/e2e/`, `playwright-core` +
установленный Google Chrome; `E2E_HEADLESS=1` — без окна, `E2E_SHOTS=<папка>` —
скриншоты шагов). Сегодняшнюю дату в приложении подменяет `?today=YYYY-MM-DD`.
